## Remediation in this batch

- **Multer 2.5.0:** fixes [pending asynchronous filter teardown DoS](https://github.com/expressjs/multer/security/advisories/GHSA-q7qp-rjg7-q26m).
  Retain the synchronous filter, single-file/5 MiB cap, MIME checks and native
  multipart/Sharp rejection regressions.
- **Zod 4.6.7:** fixes [oversized constrained collection memory exhaustion](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
  Follow the [Zod 4 migration guide](https://zod.dev/v4/changelog): use `issues`,
  the `error` customization option, explicit record key/value schemas and a typed
  request-schema boundary. Pagination defaults now run before `Number` conversion;
  previously missing optional strings became NaN before the numeric default.
  Regression tests cover nine query schemas, defaults, numeric conversion,
  fractions, invalid strings, repeated parameters and out-of-range limits.
- **Nodemailer 10.2.1:** address-parser fixes; native MIME composition plus real
  AUTH/DATA delivery to a disposable local SMTP sink. No external email is sent.
- **body-parser 1.20.9 / fast-uri 3.1.9:** compatible transitive upgrades remove
  the remaining production findings without adding new direct dependencies.
- **typescript-eslint 8.72.0:** removes the vulnerable minimatch path and supports
  the installed TypeScript version while retaining ESLint 8.57/config behavior.
- **Testcontainers 12.2.1:** coordinated core/PostgreSQL/Redis upgrade removes the
  affected busboy/undici/dockerode/uuid paths. Requires **Node >=22.22** for the
  test tooling; CI and Docker use the current Node 22 line. Actual container
  startup and integration behavior must be verified by PR CI.
- **Vitest/UI/coverage 4.1.12:** coordinated patch removes the mock registration
  and Windows redirect-allowlist advisories. Keep test server/UI off public
  interfaces; ordinary CI uses `vitest run`.

No `npm audit fix --force` or hand-edited integrity fields were used. Package
installation was performed with `--ignore-scripts` after an optional dependency
telemetry script was blocked; Prisma generation was then run explicitly. A clean
`npm ci --ignore-scripts` verifies manifest/lockfile consistency.

## Verification and remaining acceptance

Local checks: clean install, Prisma generation, unit tests (including real
Multer/Sharp, SMTP sink and migration contracts), typecheck, lint, architecture
and production build. Database/Redis integration, production image, recovery and
frontend/backend E2E require GitHub Actions because this workspace has no Docker
runtime. Use exact-head CI results before merge; do not treat local unit results
as container or hosted acceptance.

Config hardening from [PR #230](https://github.com/Thang4869/TriAD-Backend/pull/230)
remains: explicit Redis/frontend URLs, production CORS and JWT/TOTP/SMTP/Cloudinary
requirements; test defaults live only in `tests/setup-env.ts`. `API_EDGE_SECRET`
is optional for direct/local modes, and if configured requires `TRUST_PROXY=0`.

**Still pending:** real staging Cloudinary upload and OTLP collector span proof.
This batch does not change Render/Vercel configuration, deploy the new packages,
or prove external SMTP delivery. Keep #141 open pending exact-head CI and the
remaining staging acceptance; do not remove its checklist row prematurely.

## Reproduce

```sh
npm ci --ignore-scripts
npx prisma generate
npm audit --omit=dev --json > npm-audit-production.json
npm audit --json > npm-audit-all.json
node scripts/summarize-npm-audit.cjs npm-audit-production.json npm-audit-all.json
node scripts/assert-production-audit.cjs npm-audit-production.json
npm run typecheck
npm run lint
npm run architecture:check
npm run test:unit
npm run test:integration
npm run build
```

Audit exits nonzero for reported vulnerabilities. Inspect errors and all severity
counts; creating a JSON file is not proof of a successful scan. CI uploads both
JSON reports for reproducibility.
